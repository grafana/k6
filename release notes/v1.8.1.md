k6 `v1.8.1` is here! This patch release on v1.x includes:

- The cloud secret source is no longer enabled by default in `k6 cloud run --local-execution`, restoring the v1.7 behaviour that `v1.8.0` unintentionally changed.
- A fix for HTTP/2 negotiation and error classification under Go 1.27.
- Security updates for gRPC, `golang.org/x/net`, `golang.org/x/text`, `golang.org/x/crypto`, OpenTelemetry, `klauspost/compress`, and the Go toolchain.

## Breaking changes

There are no breaking changes in this release. This release *removes* a behaviour change that `v1.8.0` introduced — see the cloud secret source entry under Bug fixes.

## New features

There are no new features in this release.

## Bug fixes

### Cloud secret source is no longer enabled by default [#6274](https://github.com/grafana/k6/pull/6274)

`v1.8.0` enabled the Grafana Cloud secret source automatically for `k6 cloud run --local-execution` ([#5875](https://github.com/grafana/k6/pull/5875)). This turned out to be a breaking change for the v1.x line: scripts that configured their own secret source started failing with

```
level=error msg="Uncaught (in promise) no secret source with name \"default\" is configured"
```

This release reverts that behaviour. Explicitly configured secret sources work again as they did in `v1.7`:

```shell
k6 cloud run --local-execution --secret-source=file=secrets.file script.js
```

Fixes [#6093](https://github.com/grafana/k6/issues/6093).

### HTTP/2 negotiation and error classification under Go 1.27 [#6275](https://github.com/grafana/k6/pull/6275)

Go 1.27 changes HTTP/2 negotiation and error behaviour. This backport keeps VUs on HTTP/2, classifies connection and `GOAWAY` errors consistently across Go versions, and preserves unknown HTTP/2 error buckets. Backport of [#6234](https://github.com/grafana/k6/pull/6234).

## Maintenance and internal improvements

- [#6193](https://github.com/grafana/k6/pull/6193), [#6194](https://github.com/grafana/k6/pull/6194) Updates `google.golang.org/grpc` to `v1.82.1` [security]. Addresses [GHSA-hrxh-6v49-42gf](https://github.com/advisories/GHSA-hrxh-6v49-42gf): an xDS RBAC authorization bypass, an HTTP/2 Rapid Reset mitigation bypass causing high CPU consumption, and a server panic when parsing crafted xDS RBAC policies.
- [#6187](https://github.com/grafana/k6/pull/6187), [#6189](https://github.com/grafana/k6/pull/6189) Updates `golang.org/x/net` to `v0.56.0` [security]. Addresses [CVE-2026-46600](https://nvd.nist.gov/vuln/detail/CVE-2026-46600): parsing an invalid SVCB or HTTPS RR can panic in `dns/dnsmessage`.
- [#6188](https://github.com/grafana/k6/pull/6188), [#6190](https://github.com/grafana/k6/pull/6190) Updates `golang.org/x/text` to `v0.39.0` [security]. Addresses [CVE-2026-56852](https://nvd.nist.gov/vuln/detail/CVE-2026-56852): a `norm.Iter` can enter an infinite loop on input containing invalid UTF-8 bytes.
- [#6207](https://github.com/grafana/k6/pull/6207) Updates `go.opentelemetry.io/otel` to `v1.44.0` [security]. Addresses [CVE-2026-41178](https://nvd.nist.gov/vuln/detail/CVE-2026-41178): baggage parsing no longer caps raw header length.
- [#6220](https://github.com/grafana/k6/pull/6220) Updates `github.com/klauspost/compress` to `v1.18.7` [security]. Addresses [GHSA-259r-337f-4rfw](https://github.com/advisories/GHSA-259r-337f-4rfw): an out-of-bounds read in `s2` when encoding with a specially crafted dictionary.
- [#6135](https://github.com/grafana/k6/pull/6135) Updates the Go toolchain to `v1.25.12` [security]. Addresses [CVE-2026-39822](https://nvd.nist.gov/vuln/detail/CVE-2026-39822): on Unix systems, opening a file in an `os.Root` improperly follows symlinks outside the root when the final path component is a symlink and the path ends in `/`.
- Updates `golang.org/x/crypto` to `v0.53.0`, pulled in transitively alongside the updates above.
