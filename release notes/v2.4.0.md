k6 `v2.4.0` is here 🎉! This release includes:

- Experimental tracing of test runs, scenarios, VUs, and iterations.
- Ed25519 signatures and X25519 key agreement in WebCrypto.
- Credential-header redaction for HTTP and gRPC debug logs.
- Structured gRPC error details and more Prometheus remote-write connection options.
- Fixes for browser selectors, JavaScript memory leaks, and asynchronous error reporting.

## New features

### Trace the test execution hierarchy [#6605](https://github.com/grafana/k6/pull/6605)

The experimental `native-tracing` feature adds spans for the test run, each scenario, each VU activation, and each iteration. Browser spans become children of the corresponding iteration, so you can follow browser activity within the wider test execution.

Enable the feature and configure an OpenTelemetry traces output:

```shell
k6 run --features=native-tracing --traces-output=otel=http://localhost:4318 script.js
```

The hierarchy is `k6.run` → `scenario` → `vu` → `iteration`. Spans include scenario and execution identifiers. Failed iterations record errors, while iterations interrupted by the end of a scenario are marked as interrupted. The feature is opt-in and requires an enabled traces output.

### Sign and exchange keys with Ed25519 and X25519 [#6525](https://github.com/grafana/k6/pull/6525)

WebCrypto now supports Ed25519 signing and verification, and X25519 key agreement. Both algorithms support key generation and import/export, including JWK keys.

For example, generate an Ed25519 key pair, sign a message, and verify its signature:

```js
export default async function () {
  const keys = await crypto.subtle.generateKey('Ed25519', true, ['sign', 'verify']);
  const message = new Uint8Array([104, 101, 108, 108, 111]);
  const signature = await crypto.subtle.sign('Ed25519', keys.privateKey, message);
  const valid = await crypto.subtle.verify('Ed25519', keys.publicKey, signature, message);
  console.log(valid); // true
}
```

Thanks, @BlairCurrey!

### Hide credential headers in debug logs [#6607](https://github.com/grafana/k6/pull/6607)

Use `--http-debug-redact` with `--http-debug` to mask credential headers in HTTP requests and responses, and in gRPC metadata:

```shell
k6 run --http-debug --http-debug-redact script.js
```

Redaction covers `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie`, `X-API-Key`, `X-Auth-Token`, and `X-Amz-Security-Token`. Authentication schemes, cookie names, and cookie attributes remain visible to help with debugging. You can also enable it through `K6_HTTP_DEBUG_REDACT` or the `httpDebugRedact` script option.

Redaction is disabled by default. It only masks these headers and metadata keys; URL query parameters and bodies logged with `--http-debug=full` remain unchanged. Thanks, @digitalcrab!

### Inspect structured gRPC error details [#5711](https://github.com/grafana/k6/pull/5711)

gRPC responses now expose structured error details from `grpc-status-details-bin` through `response.error.details`. This lets scripts inspect field-validation errors, retry information, and other details supplied by a server instead of relying only on an error message.

k6 resolves both standard Google error-detail types and custom types loaded through the client. If details cannot be converted, the error still includes its code and message. See [the gRPC error-details example](../examples/grpc_error_details.js) for a complete script.

### Send HTTP QUERY requests [#6481](https://github.com/grafana/k6/pull/6481)

The new `http.query(url, body, params)` convenience method sends an HTTP `QUERY` request. It accepts a request body and the same request parameters as the other HTTP convenience methods.

```js
import http from 'k6/http';

export default function () {
  http.query('https://example.com/search', JSON.stringify({ term: 'k6' }), {
    headers: { 'Content-Type': 'application/json' },
  });
}
```

Thanks, @ashrafiucse!

### Configure a proxy for Prometheus remote write [#6403](https://github.com/grafana/k6/pull/6403)

The Prometheus remote-write output now accepts a proxy through `K6_PROMETHEUS_RW_PROXY` or the `proxy` output argument:

```shell
K6_PROMETHEUS_RW_PROXY=http://localhost:8080 \
k6 run --out experimental-prometheus-rw script.js
```

When this option is unset, the output continues to connect without a proxy.

## UX improvements and enhancements

- [#6528](https://github.com/grafana/k6/pull/6528) Adds `K6_PROMETHEUS_RW_SIGV4_TOKEN` for AWS session credentials when signing Prometheus remote-write requests. Use it together with the existing region, access-key, and secret-key options. Thanks, @ashrafiucse!
- [#6483](https://github.com/grafana/k6/pull/6483) Supports fetching intermediate TLS certificates supplied as PKCS#7/CMS bundles, including PEM-armored bundles, when `tlsAIAFetch` is enabled. This allows certificate-chain completion with more certificate authorities. Thanks, @ashrafiucse!
- [#6565](https://github.com/grafana/k6/pull/6565) Accepts the standard `TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256` and `TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256` cipher-suite names while preserving the existing aliases. Thanks, @HakeemTheEmperor!
- [#6561](https://github.com/grafana/k6/pull/6561) Includes the searched path in errors for missing local files. Thanks, @kriyanshii!
- [#6581](https://github.com/grafana/k6/pull/6581) Adds the missing script argument to two `k6 run` help examples. Thanks, @ZainnQureshii!

## Bug fixes

- [#6637](https://github.com/grafana/k6/pull/6637) Makes `browserContext.pages()` return pages in attachment order instead of an unpredictable order, preserving the order of remaining pages when a page closes. Thanks, @adityareddy-dev!
- [#6629](https://github.com/grafana/k6/pull/6629) Fixes a JavaScript memory leak introduced in v2.2.0: WeakMap entries whose values reference their keys can now be collected again. This affects scripts using, for example, the jslib URL polyfill.
- [#6614](https://github.com/grafana/k6/pull/6614) Reports an error when a script function returns a promise that remains pending after the event loop has no work left to settle it. Normal interruption at the end of a scenario or test does not produce this error. Thanks, @muhammadmobi!
- [#6406](https://github.com/grafana/k6/pull/6406) Reports unhandled promise rejections as script exceptions, with the corresponding script-error abort reason and an `unhandled script exception` log hint.
- [#6587](https://github.com/grafana/k6/pull/6587) Prevents panics when formatting unhandled promise rejections whose stack access, string conversion, or export executes JavaScript.
- [#6578](https://github.com/grafana/k6/pull/6578) Fixes browser `text=` and bare quoted selectors, `visible=false` matching, and selector chaining after a visibility filter. Also fixes stale `hasText`/`hasNotText` results after DOM updates, escaping of text and regular-expression values, accessible names containing CRLF, and chained selectors across nested open shadow roots, including `nth()` and `all()`.
- [#6496](https://github.com/grafana/k6/pull/6496) Uses the encoded transfer size reported by Chrome for `browser_data_received`, including redirects. Values can differ from earlier releases, particularly for compressed responses, so existing thresholds and comparisons might need adjustment. Thanks, @Saad259!
- [#6390](https://github.com/grafana/k6/pull/6390) Makes request objects reflect URL, method, header, and body overrides from `route.continue()` before request events are emitted.
- [#6167](https://github.com/grafana/k6/pull/6167) Prevents empty duplicate browser navigation spans on client-side redirects, while preserving tracing for navigation after a download or a response that does not commit a document.
- [#6568](https://github.com/grafana/k6/pull/6568) Prevents screenshot-upload errors from exposing credentials or internal storage URLs, and avoids echoing secret values in screenshot-output configuration errors.
- [#6567](https://github.com/grafana/k6/pull/6567) Preserves `=` characters inside `K6_BROWSER_SCREENSHOTS_OUTPUT` configuration values.
- [#6591](https://github.com/grafana/k6/pull/6591) Reports browser initialization configuration errors without panicking.
- [#6381](https://github.com/grafana/k6/pull/6381) Returns a regular 401 response with an empty body when digest authentication finds no usable challenge, instead of reporting a closed-response-body error. Replaces the unmaintained digest-authentication library. Thanks, @ashrafiucse!
- [#6486](https://github.com/grafana/k6/pull/6486) Prevents digest authentication from removing credentials from a shared `http.url` value used by subsequent requests. Thanks, @ashrafiucse!
- [#6575](https://github.com/grafana/k6/pull/6575) Fixes a race between HTTP transport initialization and WebSocket or gRPC use of the same VU's TLS configuration.
- [#6590](https://github.com/grafana/k6/pull/6590) Treats HTML `checked` and `disabled` attributes as boolean attributes during form serialization, so their presence determines their effect regardless of their value.
- [#6489](https://github.com/grafana/k6/pull/6489) Supports ECDH `deriveBits` lengths that are not multiples of eight and clears unused trailing bits. Thanks, @hyuraku!
- [#6379](https://github.com/grafana/k6/pull/6379) Rejects creating a `k6/websockets` connection in the init context with an error.
- [#6610](https://github.com/grafana/k6/pull/6610) Reports gzip finalization errors in compressed CSV and JSON output, as well as buffered-write errors when closing compressed JSON output. Thanks, @skdas20!
- [#6497](https://github.com/grafana/k6/pull/6497) Marks the ramping-arrival-rate progress bar as complete when the executor finishes early.
